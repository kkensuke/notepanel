# notepanel 履歴機能 設計書

- 状態：実装済み。決定事項は §10 にまとめた。
- 作成：2026-11-14
- 対象のコード：`kkensuke/notepanel` の `c339216`
- 関連：`docs/design.md` の §5.3（ノートとファイル）、§5.7（保存）、§5.8（設定）、§5.9（ブリッジのメッセージ）、§6（ショートカット一覧）

## 1. 目的と範囲

ノートの過去の状態をさかのぼり、必要な部分を取り出せるようにする。想定する場面は編集の誤りである（昨日消した段落を戻したい、など）。

次の 2 つは範囲外とする。

- ディスクの故障や紛失への備え。Time Machine やクラウドの同期に任せる。
- 過去の版でノートを置き換える「復元」。履歴画面はコピーだけを提供する（§4.4）。

## 2. 現状と課題

現在の実装（`NoteStore.backUp`、`docs/design.md` §5.7）は次のとおりである。

- 保存でファイルを上書きする直前に、元の内容を `~/Library/Application Support/notepanel/Backups/` に `日時 名前.md` として書く。名前は先頭 100 文字まで。
- 1 ノートにつき最短 10 分ごと（`backupInterval`）。直前に版を作った時刻は、メモリ上の `lastBackup` で覚える。空のファイルは残さない。版を書けなくても保存は続ける。
- 起動時に、更新日時が 30 日より古い版を消す（`pruneBackups`）。
- メニューバーアイコンの「Open Backups Folder」で Finder に開く。

次の 2 点は良い設計なので引き継ぐ。

- 版は変更があったときにしか作られない。
- 版は普通の `.md` で、アプリの外からも読める。

課題は次の 5 つである。

1. 版がノート名で 1 つのフォルダに並ぶ。1 行目への追従で名前が変わると、同じノートの版が別々の名前に散る。
2. 30 日以内の版は 10 分刻みですべて残り、30 日を過ぎるとすべて消える。古い版ほど粗くてよいのに、粒度が一定である。
3. 間引きは起動時にしか動かない。常駐アプリなので、何週間も動かないことがある。
4. 版を見るには Finder で探すしかない。
5. 版の保存先は固定で、変えられるのはノートのフォルダだけである。そのため、次の 2 つが起きる。
   - 版をクラウドのフォルダに置けない。
   - 複数のノートのフォルダを使い分けると、同じ名前のノート（たとえばフォルダ X と Y の「Todo」）の版が混ざる。

## 3. 評価基準

保存の方式、保存先、見せ方は独立に決められるので、それぞれに基準を置く。

表1：評価基準

| 対象 | 基準 | 内容 |
|---|---|---|
| 保存の方式 | 確実さ | 版が壊れたり消えたりしないか。1 つの版が壊れても、他の版に影響しないか |
| | 単純さ | コードの量、依存の数、既存の構成（`NoteStore`、`Logic.swift`、`NotepanelChecks`）との整合、テストのしやすさ |
| | 容量 | ディスクの使用量 |
| | 透明性 | アプリの外（Finder、grep、Quick Look）から読めるか |
| | 性能 | 300 ms ごとの自動保存を遅くしないか |
| 保存先 | 設定の単純さ | 設定項目の数と、意味の分かりやすさ |
| | 方針との整合 | ノートのフォルダには何も書かない（`docs/design.md` §5.3、§5.4）という方針を守れるか |
| | 置き場所 | 履歴もクラウドのフォルダに置けるか。既存の任意のフォルダを、そのままノートのフォルダにできるか |
| | 追従 | ノートのフォルダを移動・同期したとき、履歴もついてくるか |
| | 分離 | 複数のノートのフォルダを使っても、履歴が混ざらないか |
| | 互換 | 今の設定をそのまま使えるか |
| 見せ方 | 見つけやすさ | 目的の版まで何操作でたどり着けるか |
| | 安全さ | 操作を誤っても、今のノートが変わらないか |

## 4. 検討した案と結論

### 4.1 保存の方式：全文コピーを続ける

表2：保存の方式の比較

| 基準 | 全文コピー（現状） | 差分の連鎖 | git に自動コミット | macOS の版管理（`NSFileVersion`） |
|---|---|---|---|---|
| 確実さ | ◎ 各版が独立している | △ 途中の 1 つが壊れると、それ以降を戻せない | ○ 堅牢。ただし外部の仕組みに頼る | △ 下の注を参照 |
| 単純さ | ◎ すでにある | × 差分の作成と適用に加え、間引くときに差分の合成が要る | × プロセスの起動が要る。間引くには履歴の書き換えが要る | △ API は小さいが、挙動の文書が乏しく検証しにくい |
| 容量 | ○ 間引けば十分小さい（§5.3） | ◎ | ◎ | ◎（OS が管理する） |
| 透明性 | ◎ 普通の `.md` | × 専用の形式 | ○ git を使える人なら読める | × アプリの外からほぼ見えない |
| 性能 | ◎ 10 分に 1 回、小さなファイルを書くだけ | ○ | △ コミットのたびにプロセスを起動する | ○ |

注：`NSFileVersion` の版は、文書と同じボリュームの隠しフォルダ `.DocumentRevisions-V100` に保存される。そのため、ExFAT のような macOS 標準以外のファイルシステムや、AFP・SMB・NFS で接続したネットワークボリュームでは版が残らない。また、ファイルを別のボリュームへ移すと版が失われる（出典は末尾）。notepanel は保存先のフォルダを利用者が選べるので、この制約は合わない。

結論：全文コピーを続ける。容量は間引きで抑える（§5.3）。差分で詰めるほどの容量にはならない。

### 4.2 版を作る時機：変更したときだけ

定時（1 時間ごとなど）のスナップショットは作らない。変更したときにだけ版を作る今の方式なら、編集していないノートの版は増えず、重複を除く処理も要らない。最初に挙げた「1 時間・1 日・1 週」という粒度は、間引きの区切りとして実現する（§5.3）。

### 4.3 保存先：notepanel フォルダを選ぶ

表3：保存先の比較

| 基準 | A：App Support に固定（現状） | B：履歴フォルダも別に選ぶ | C：notepanel フォルダを選び、中に Notes と History を置く | D：ノートのフォルダ内に隠しフォルダを置く |
|---|---|---|---|---|
| 設定の数 | 1 | 2 | 1 | 1 |
| 方針との整合 | ◎ | ◎ | ◎ | × ノートのフォルダに隠しフォルダを書く |
| 履歴もクラウドに置ける | × | ◎ | ◎ | ◎ |
| 任意のフォルダをノートのフォルダにできる | ◎ | ◎ | × 中の `Notes` に限られる | ◎ |
| 追従 | × | △ 2 つを自分で移す | ◎ | ◎ |
| 分離 | △ フォルダごとに分ける処理が要る | △ 履歴フォルダを替え忘れると混ざる | ◎ | ◎ |
| 互換 | ◎ | ◎ | × 設定の意味が変わる（既定のままなら影響しない） | ◎ |
| コード | 小 | 中（設定項目が増える） | 小 | 最小 |

結論：C を採る。設定画面で notepanel フォルダを選び、その中にノート（`Notes`）と履歴（`History`）を置く。

- 履歴をクラウドで管理したいという要望を満たす。ノートと履歴が必ず 1 組で切り替わるので、追従と分離の問題も生じない。
- ノートのフォルダには何も書かないという方針を守れる。履歴は隠しフォルダにならず、Finder から普通に見える。ノートのフォルダを git で管理していても、`.gitignore` に何かを加える必要がない。
- 代償は 2 つあり、どちらも小さい。
  - 任意のフォルダを、そのままノートのフォルダにはできない。ただし、notepanel は他のツールとフォルダを共有しない方針なので、困る場面はほぼない。
  - 今の設定の意味が変わる。ただし、既定の配置（`~/Library/Application Support/notepanel/Notes`）はディスク上で変わらないので、影響を受けるのはノートのフォルダを変更している利用者だけである（§6）。

経緯：議論の途中では一度 D を推した。しかし、C の欠点として挙げた「選んだフォルダとノートのフォルダが別物になる」は、`~/Dropbox` そのものを親に選ぶ例で考えたためだった。`~/Dropbox/notepanel` のような専用フォルダを選ぶ前提なら、この欠点は当たらない。そのため C に改めた。

### 4.4 見せ方：コピーだけの履歴画面

表4：見せ方の比較

| 案 | 見つけやすさ | 安全さ | コード |
|---|---|---|---|
| Finder だけ（現状） | × 名前と日時で探す | ◎ | なし |
| 復元できる履歴画面 | ◎ | △ 誤って復元すると、今の状態が分からず慌てる | 中（復元の前に今の本文を 1 版残す処理と、本文の置き換えが要る） |
| コピーだけの履歴画面 | ◎ | ◎ ノートを書き換える経路がない | 小 |

結論：コピーだけの履歴画面にする。全体を戻したいときは、全文をコピー → Esc → ⌘A ⌘V で戻せる。手順はすべて目に見え、⌘Z で取り消せる。

### 4.5 保持期間：設定で選び、notepanel フォルダに保存する

保持期間（週に 1 つ残す段の終わり）は、設定画面で「1 年」と「無期限」から選ぶ。既定は「無期限」とする。

設定で選べるようにすると、次の 2 つの懸念がある。それぞれ次のように対処する。

- 期間を短くすると、古い版が消えて元に戻せない。→ 短くするときは確認を出し、承認されたときだけ消す（§5.6）。
- 同じ notepanel フォルダを複数の Mac から使い、Mac ごとに期間が違うと、短い方の Mac が古い版を消し、その削除が同期される。→ 期間を Mac ごとの設定（`UserDefaults`）ではなく、notepanel フォルダの `settings.json` に保存する。こうすれば、設定もフォルダと一緒に同期される。

`settings.json` が読めないとき（ファイルがない、壊れている、知らない値が入っている）は「無期限」として扱う。読み取りに失敗しても、版が消える側には倒れない。

### 4.6 処理を単純にする工夫

あえて分かりやすい規則を 1 つ加え、その代わりに別の処理や制約をなくせるものを採った。

表5：採った工夫

| 工夫 | 加えるもの | なくなるもの | 節 |
|---|---|---|---|
| 古い履歴を退ける | ノートが新しい名前を得るとき、同じ名前の古い履歴フォルダを `(old …)` に改名する | 消したノートの版と、同じ名前の新しいノートの版が混ざること。ゴミ箱へ移すときの特別な処理（そのため「戻す」で履歴がつながる） | §5.4 |
| 版のファイル名を、直前に版を作った時刻の記録として使う | 版を作る前に、そのノートのフォルダでいちばん新しい版の日時を見る | メモリ上の `lastBackup` と、改名時の付け替え（利用者の改名で漏れている今の不具合も消える）と、`setFolder` での初期化。再起動の直後に余分な版ができること。他の Mac が少し前に作った版を無視して、版を重ねて作ること | §5.2 |
| 版の日時を UTC からのずれ付きで書き、間引きの区切りを UTC の固定長にする | ファイル名に `+0900` のようなずれを付ける | `Calendar` による区切りの計算と、夏時間をまたぐテスト。Mac ごとにタイムゾーンが違うとき（旅行先のノートパソコンなど）に、版の日時と区切りがずれること | §5.2、§5.3 |

検討したが、次の 3 つは採らなかった。

- 保存のたびに版を書き、間引きで減らす（間隔の判定をなくせる）。保存は 300 ms ごとに起きうるので、そのたびにファイルの作成と削除が起き、クラウドの同期の負担が大きい。
- 起動時にも全ノートの版を間引く（他の Mac で期間を短くしたときの反映の遅れをなくせる）。起動のたびに全フォルダを読むことになる。遅れても最終的な結果は同じなので、要らない。
- 版を「ノートを開いている間に 1 つ」にする（時刻による間隔をなくせる）。長く書き続けると、途中の状態が残らない。

## 5. 仕様

### 5.1 フォルダの構成

```
<notepanel フォルダ>/          既定は ~/Library/Application Support/notepanel
├── Notes/                     ノート（*.md）
├── History/                   版
│   └── <ノート名>/
│       ├── 2026-11-14 203000 +0900.md
│       └── 2026-11-14 191500 +0900.md
└── settings.json              保持期間（§5.6）。期間を変えたときに作る
```

- notepanel フォルダは設定画面で選ぶ（§5.6）。既定のままなら、ノートの場所は今と変わらない。
- `Notes` と `History` は、なければ作る。
- `Notes` には今までどおりノートしか書かない。`NoteStore.list()` は `Notes` の直下しか見ないので、`History` がノートとして表示されることはない。
- `History` の下のフォルダの名前は、ノートの名前と一致させる。もう存在しないノートの履歴は、同じ名前が次に使われたときに `<名前> (old <日時>)` に改名して退ける（§5.4）。
- notepanel フォルダをクラウドのフォルダに置けば、ノート、履歴、保持期間が一緒に同期される。

### 5.2 版を作る

- 版を作る時機、間隔（最短 10 分）、空のファイルを残さないこと、失敗しても保存を続けることは、現状と同じ（§2）。
- 間隔は、そのノートの履歴フォルダでいちばん新しい版の日時から測る。メモリ上の `lastBackup` は廃止する（§4.6）。
  - 再起動しても、改名しても（フォルダごと移るので）、他の Mac が版を作っても、同じ規則で判定できる。
  - 版を作らない保存では、フォルダを 1 回読むだけで済む。版を作ったときは、間引き（§5.3）のためにもう 1 回読む。フォルダの中は多くても数百のファイルなので、300 ms ごとの保存を遅くしない。
- 版は `History/<ノート名>/<日時>.md` に置く。
  - `<日時>` は `yyyy-MM-dd HHmmss Z`、つまりローカル時刻と UTC からのずれである（例：`2026-11-14 203000 +0900`）。ずれを付けるので、別のタイムゾーンの Mac で読んでも同じ時刻になる。同じ名前のファイルがあれば ` 2`、` 3` …を付ける（`makeUniqueName`）。
  - ノート名はフォルダ名にだけ使うので、先頭 100 文字への切り詰めは要らなくなる。
- 版の日時はファイル名から読む。更新日時は、同期やコピーで変わりうるため使わない。
- ファイル名を日時として読めないファイル（利用者が置いたものなど）は、履歴画面に出さず、間引きでも消さない。

### 5.3 間引き

表6：残す版

| 版の古さ | 残す版 | 最大数（目安） |
|---|---|---|
| 1 時間以内 | すべて（最短 10 分間隔） | 6 |
| 1 時間〜1 日 | 1 時間ごとに最新の 1 つ | 24 |
| 1 日〜1 週 | 1 日ごとに最新の 1 つ | 7 |
| 1 週〜保持期間の終わり | 1 週ごとに最新の 1 つ | 1 年なら 53、無期限なら年に 53 ずつ増える |
| 保持期間より前 | 削除（無期限なら該当なし） | 0 |

- 区切りは、UTC の 1970 年 1 月 1 日から数えた固定長（1 時間、1 日、1 週）とする（§4.6）。
  - タイムゾーンや夏時間によらず、どの Mac でも同じ版が残る。
  - 日本時間では日の区切りが 9 時になるが、区切りの位置は利用者には見えないので、問題にならない。
  - 「今から何時間前か」で区切ると、間引くたびに残る版がずれる。固定の区切りなら、何度間引いても結果は変わらない。
- 版を書いた直後に、そのノートの版だけを間引く。保持期間はそのたびに `settings.json` から読むので、他の Mac で変えた期間も、同期されたあとに反映される。
- 起動時の一括処理（`pruneBackups`）と 30 日ルールは削除する。全ノートの版を一度に間引くのは、保持期間を短くしたとき（§5.6）だけである。このときは、`(old …)` に退けたフォルダ（§5.4）も間引く。
- 間引きの規則は、純粋関数として `Logic.swift` に置く。`limit` が `nil` なら無期限を表す。

```swift
/// The versions to keep: all from the last hour, then the newest in each hour for a day,
/// in each day for a week, and in each week until `limit` (nil keeps them all).
public func versionsToKeep(_ dates: [Date], now: Date, limit: TimeInterval?) -> Set<Date> {
    let hour: TimeInterval = 60 * 60, day = 24 * hour, week = 7 * day
    var kept = Set<Date>(), buckets = Set<[TimeInterval]>()
    for date in dates.sorted(by: >) {
        let size: TimeInterval
        switch now.timeIntervalSince(date) {
        case ..<hour: kept.insert(date); continue
        case ..<day: size = hour
        case ..<week: size = day
        case ..<(limit ?? .infinity): size = week
        default: continue
        }
        // Fixed lengths from 1970 in UTC, so every Mac keeps the same versions in any time zone.
        let bucket = [size, (date.timeIntervalSince1970 / size).rounded(.down)]
        if buckets.insert(bucket).inserted { kept.insert(date) }
    }
    return kept
}
```

容量の目安：10 KB のノートを毎日編集しても、版は 1 年あたり 1 MB 未満にとどまる（「1 年」なら合計でおよそ 90 版で頭打ちになる）。一方、現状では 1 日 4 時間編集すると、30 日で 720 版（約 7 MB）が残り、しかも 30 日より前には戻れない。

### 5.4 改名、別名保存、削除

ノートの履歴は、ノートと同じ名前のフォルダ（`History/<ノート名>`）で探す。そのため、履歴フォルダの名前はノートの名前に合わせ続ける。

- 改名：`NoteStore.move` で、ノートのファイルと一緒に `History/<旧名>` を `History/<新名>` へ移す。
  - `move` は、利用者の改名（`rename(_:to:)`）と 1 行目への追従（`renameToFirstLine`）の両方が通るので、ここ 1 か所を変えれば済む。
  - 順序：まずノートのファイルを移す。それができてから、古い履歴を退け（下記）、履歴フォルダを移す。ノートのファイルを移せなければ、履歴には触れない。
  - 版を作る間隔は履歴フォルダから測るので（§5.2）、フォルダを移せば間隔の判定もついてくる。今の `lastBackup` の付け替え（`renameToFirstLine` でしか行っておらず、利用者が改名したときに漏れている）は要らなくなる。
- 古い履歴を退ける：ノートが新しい名前を得るときに、`History/<新しい名前>` がすでにあれば、そのフォルダを `<名前> (old yyyy-MM-dd HHmm)` に改名してから進める。
  - ノートが新しい名前を得るのは、次の 3 か所である：新規作成（`create`）、改名と 1 行目への追従（どちらも `move`）、衝突による別名保存（`flush`）。
  - 退けても安全な理由：`Notes` の中ではノートの名前が重ならない。そのため、新しい名前と同じ名前の履歴フォルダがあれば、それは必ずもう存在しないノートの残りである（アプリで消した、Finder で消した、Finder で名前を変えた、など）。
  - 日時は退けた時刻（ローカル時刻）とし、書式は既存の `conflictName`（`<名前> (conflict 2026-11-07 1530)`）に合わせる。同じ名前があれば ` 2`、` 3` …を付ける（`makeUniqueName`）。
  - 大文字・小文字だけの改名（`todo` → `Todo`）では退けない。大文字・小文字を区別しないボリュームでは、`History/todo` と `History/Todo` は同じフォルダなので、退けると自分の履歴をどかしてしまう。`rename(_:to:)` と同じく `isSameFile` で判定する。
  - 退けるのに失敗しても、ノートの作成や改名は続ける。そのときは版が混ざるが、失われはしない。版を書けなくても保存を続けるのと同じ考え方である。
  - 退けたフォルダは、Finder（「Open History Folder」）から見るためのものとする。履歴画面には出さない。
- 衝突による別名保存：別名で保存したノートは新しいノートとして扱い、元の名前の履歴は移さない。
- ゴミ箱へ移す：履歴フォルダは名前を変えずに残す。そのため、Finder の「戻す」でゴミ箱から戻したノートには、同じ名前がまた使われるまで、履歴がそのままつながる。消したノートの版は、メニューの「Open History Folder」から取り出せる。

### 5.5 履歴画面

- 開閉：⌘Y。切替画面（⌘P）と同じく、パネル全体を覆う。開いている間、ノートは見えなくなるだけで、何も変わらない。⌘P と ⌘Y は同時に開かず、一方を開くと他方は閉じる。
- 対象：開いているノートの版を、新しい順に並べる。
- 配置：上に版の一覧、下に選んだ版の本文を置く。本文は `<pre>` で読み取り専用に表示し、フォントと文字サイズはノートと同じにする。
- 一覧の行：日時と、全文をコピーするボタンを置く。
  - ボタンはリンクの Copy ボタンと同じアイコンで、押すと 1.5 秒間 ✓ になる。
  - 日時は UI の言語（英語）で表示する。例："Today 14:20"、"Yesterday 9:05"、"Nov 3, 14:20"。1 年以上前は "Nov 3, 2025" のように年を付ける。日時の書式を作る関数は `editor/src/logic.js` に置く。
- 版がひとつもなければ "No earlier versions" と表示する。
- 履歴画面には、ノートを書き換える経路を持たせない。
- データの受け渡し：⌘Y を押すと、Swift が版を読み、本文ごとまとめて JS に送る。shortcut：版が多いノートや大きなノートで送る量が重くなったら、選んだ版だけを読む方式に替える。

表7：履歴画面のキー

| キー | 動作 |
|---|---|
| ↑ / ↓ | 版を選ぶ |
| ↩ | 選んだ版の全文をコピーする |
| ⌘A | 本文だけを全文選択する（一覧は選ばない） |
| ⌘C | 本文で選んだ部分をコピーする |
| Esc / ⌘Y | 閉じてノートに戻る |

### 5.6 設定画面

**Data folder**

- 見出し「Notes folder」を「Data folder」に改め、ここで notepanel フォルダを選ぶ。「Use Default」と「Choose…」はそのまま残す。
- 選んだパスの下に、中の `Notes` と `History` のパスを小さく表示する。誤って既存の Notes フォルダそのものを選んだ場合（`Notes/Notes` ができてしまう場合）も、これで気づける。この誤りを自動で検出する処理は作らない。
- 設定のキーは `folder` から新しいキー `dataFolder` に替える。既定は `~/Library/Application Support/notepanel`（§6）。
- フォルダを切り替えたら、`NoteStore.setFolder` でノートのフォルダ、履歴フォルダ、`settings.json` の場所をまとめて替える。今は `backups` が `let` なので、ノートのフォルダしか替わらない。

**Keep history**

- Data folder の欄に、保持期間を選ぶメニュー「Keep history」を置く。選択肢は "For 1 year" と "Forever" で、既定は "Forever" とする。
- 値は `<notepanel フォルダ>/settings.json` に `{"keepHistory": "1 year"}` または `{"keepHistory": "forever"}` として保存する。`UserDefaults` には置かない（§4.5）。ファイルがなければ "Forever" として扱い、期間を変えたときに初めて作る。
- 設定画面を開いたときと、notepanel フォルダを切り替えたときに、`settings.json` を読み直して表示する。
- "Forever" から "For 1 year" に変えるときは、次の確認を出す。
  - 文言：「Delete versions older than 1 year?」と「This deletes them for every note in this data folder. You can’t undo this.」
  - ボタン：「Delete」（`hasDestructiveAction`）と「Cancel」。元に戻せない操作なので、既定ボタン（↩）は「Cancel」にする。ゴミ箱への移動の確認（既定ボタンが実行側）とは扱いを変える。
  - 「Delete」を選んだら、`settings.json` を書き、続けて全ノートの版を一度に間引く。`settings.json` を書けなかったら、メニューを元に戻し、何も消さない。
  - 「Cancel」を選んだら、メニューを元に戻す。
- "For 1 year" から "Forever" に変えるときは、確認を出さずに `settings.json` を書く。すでに消えた版は戻らない。

## 6. 移行

- 30 日ルール、`pruneBackups`、`Prefs.backups` を削除する。
- 旧 `Backups/` は残す。新しいコードは旧 `Backups/` を読まず、中身を `History` へ移す処理も、消す処理も作らない。移さない理由は、古い版がノート名で並んでいて、ノートの名前は 1 行目に追従して変わるため、どの版がどのノートのものかを確実には対応づけられないことである。不要なら利用者が手動で消す。
- 設定キー `folder` からの移行コードは書かない。
  - 既定のフォルダのままなら、何もしなくてよい（ノートの場所は変わらない）。

## 8. テスト

`NotepanelChecks` で次を確かめる。

- `versionsToKeep`：
  - 各段の区切りで、最新の 1 つだけが残る。
  - `limit` が 1 年なら 1 年より前の版が消え、`nil` なら週に 1 つが残り続ける。
  - 一度間引いた結果にもう一度適用しても、結果が変わらない。
- 版のファイル名：あるタイムゾーンで書いた名前を、別のタイムゾーンを既定にした状態で読んでも、同じ時刻になる。後ろに ` 2` が付いた名前も読める。
- 保持期間の読み取り：`settings.json` がない、壊れている、知らない値が入っている場合は、どれも無期限になる。
- 版が `History/<ノート名>/` に書かれる。空のノートの版は残さない。間隔より短いあいだは、新しい版を作らない（既存のテストを書き換える）。`NoteStore` を作り直しても（再起動に当たる）、改名のあとでも、間隔の判定は変わらない。
- 利用者の改名でも、1 行目への追従でも、履歴のフォルダが移る。
- 古い履歴を退ける：
  - 消したノートと同じ名前のノートを作ると、古い履歴フォルダが `<名前> (old …)` に退けられ、新しいノートの版は空のフォルダから始まる。
  - 改名の移動先に古い履歴フォルダがあれば、それを退けてから移す。
  - 大文字・小文字だけの改名では、自分の履歴を退けない。
  - ゴミ箱へ移しても、履歴フォルダの名前は変わらない。
- 日時として読めない名前のファイルは、一覧に出ず、間引きでも消えない。
- 全ノートの版の一括の間引きで、すべてのノートのフォルダに規則が適用される。
- `setFolder` のあと、版と `settings.json` が新しい notepanel フォルダで読み書きされる。

`editor/test/logic.test.js` で、日時の書式を作る関数（Today、Yesterday、同じ年、前の年）を確かめる。

`editor/smoke/browser.mjs`（ヘッドレス Chrome）で、履歴画面を確かめる：⌘Y で開いて本文が見えなくなること、↑↓ で選ぶこと、↩ と行のボタンでのコピー、⌘A が本文だけを選ぶこと、Esc で閉じてノートが変わっていないこと、版がないときの表示、⌘Y・切替画面・別のノートを開くことで閉じること。

## 9. 既知の制約

- Finder でノートの名前を変えると、版は旧名のフォルダに残り、ノートから切り離される。旧名が次に使われたときには `(old …)` に退けられる。どちらの場合も、版は消えずに「Open History Folder」から見える。
- `(old …)` の日時は退けた時刻で、ノートを消した時刻ではない。最後に編集したおおよその時刻は、フォルダの中でいちばん新しい版のファイル名から分かる。
- 複数の Mac で同じ notepanel フォルダを使う場合：
  - 他の Mac で作ったノートの履歴フォルダが、ノート本体より先に同期されてくると、そのノートの履歴を古い残りと誤認して `(old …)` に退けることがある。
  - 保持期間を短くしたとき、その Mac では全ノートの版をすぐに間引く。他の Mac では、各ノートの版を次に作ったときに間引く。どちらも規則は同じなので、結果は一致する。
- 履歴画面で本文の一部をコピーするには、マウスで選ぶ必要がある（本文を `<pre>` で表示するため）。キーボードで選びたくなったら、読み取り専用の CodeMirror に替える。
- notepanel フォルダを消すと、履歴も一緒に消える。ディスクの故障に備えるのは Time Machine などの役目とする（§1）。
- 未確認：iCloud Drive の「Mac のストレージを最適化」で、版のファイルや `settings.json` がローカルから外された場合の挙動。ダウンロードされるまで読めないはずである。`settings.json` が読めなければ無期限として扱うので、版が消える側には倒れない。
