## 1. 目的と範囲

切替画面（⌘P で開く、ノートを探して開く画面）を、上に検索欄と一覧、下に選択中の行のノートを表示する画面にする。検索中は、検索語を含む本文の行を 1 行ずつ一覧に並べる。行を開くと、ノートを同じ位置に表示し、その検索語でノート内検索を始める。

設計では、次の 4 点を方針とした。

- 現行の動作は、変える利点が明確な場合にだけ変える。
- コードの変更を小さくする。
- 説明がないと使えない機能を加えない。
- 行の高さと余白をそろえ、見た目を整える。

対象は、切替画面の呼び出しから、選んだノートを開くまでである。ノート内検索のバーと、⌘Y で開く以前の版の画面の見た目は対象外とする。

## 4. 仕様

### 4.1 呼び出しと閉じ方

切替画面を開く操作は、現行から変えない。操作は表 3 の 4 つである。

表3：切替画面を開く操作

| 操作 | 切替画面が閉じているとき | 切替画面が開いているとき |
|---|---|---|
| ⌘P（パネル内） | 開く | 閉じる |
| タイトルバーの一覧ボタン | 開く | 閉じる |
| メニューバーアイコンのメニューの「Search Notes」 | パネルを表示して開く | 検索欄を初期値に戻して開き直す |
| Search notes のホットキー | パネルを表示して開く | 検索欄を初期値に戻して開き直す |

開いた直後は、検索欄にフォーカスを置いて検索欄の文字列を全選択し、一覧の先頭の行を選ぶ。以前の版の画面が開いていれば閉じる。

検索欄の初期値は、次のように決める。

- 開いているノートでノート内検索が開いていれば、その検索語を検索欄に入れる。開いているノートにない語を、続けてほかのノートから探せるようにするためである。
- ノート内検索が開いていないか、正規表現であれば、検索欄を空にする。
- ノート内検索が、切替画面で行を開いたときに始まったもの（§4.7）であれば、検索欄を空にする。その検索は済んでいるので、持ち越さない。利用者がノート内検索の語を書き換えた場合は、利用者自身の検索として持ち越す。

Esc で切替画面を閉じ、フォーカスをノートに戻す。ホットキーかメニューの「Search Notes」で、隠れていたパネルを出して切替画面を開いた場合は、Esc の 1 回で切替画面を閉じ、パネルも隠す。現行では Esc を 2 回押す必要がある。

このほか、⌘P を押す、タイトルバーの一覧ボタンをクリックする、行を開く、フッターにメッセージが出る、のいずれかで切替画面を閉じる。いずれも現行と同じである。

### 4.2 画面の構成

切替画面は、上から順に、シート、境界バー、プレビューの 3 つで構成し、パネル全体を覆う。検索中の構成を図 1 に示す。

```
┌────────────────────────────────────┐
│ ○ budget                   3 notes │  検索欄
├────────────────────────────────────┤
│   Budget 2026                      │  見出し
│   │ Hardware budget was cut.       │  一致行（選択中の行）
│   │ Q1 | budget review |           │  一致行
│   Weekly plan                      │  見出し
│   │ Send the budget draft to Mika  │  一致行
├───────────────── ━━ ───────────────┤  境界バー
│ # Budget 2026                      │
│ Hardware budget was cut.           │  プレビュー
│ | Q1 | budget review |             │
└────────────────────────────────────┘
```

図1：検索中の切替画面。上から、シート（検索欄と一覧）、境界バー、プレビュー

シートは、次のように作る。

- 検索欄は、入力欄に枠を付けず、左に虫眼鏡のアイコン、右端に件数表示を置く。検索欄と一覧の間には、細い罫線を引く。
- 一覧は検索欄の下に置く。行が収まらないときは、一覧だけをスクロールする。
- シートの背景はパネルと同じ色で塗り、下のノートを透かさない。

プレビューの高さは、利用者が境界バーをドラッグして決める。プレビューを使わない利用者が、現行と同じ表示にできるようにするためである。

- 高さは、切替画面の高さに対する割合として持つ。既定は 0.4 とする。
- 最小は 0 とする。0 にすると一覧がパネル全体を使い、現行と同じ表示になる。
- ドラッグ中に高さが 24 px 未満になったら、0 にする。その高さでは、本文を 1 行も表示できないためである。
- 最大は、検索欄とピン留めしたノートの行が残る高さまでとする。ピン留めが 2 件未満のときは、2 行分を残す。
- 高さが 0 のときも、境界バーはパネルの下端に残す。ドラッグすれば、プレビューを戻せる。
- 割合は、ドラッグを終えたときに保存し、次に開いたときも使う（§5）。

各部の寸法を表 4 に示す。値は、表示の文字サイズが既定の 15 px の場合である。

表4：各部の寸法（表示の文字サイズが 15 px の場合）

| 部分 | 寸法 | 決め方 |
|---|---|---|
| ノート行の高さ（検索欄が空のとき） | 30 px | 表示の文字サイズの 2 倍 |
| 見出しと一致行の高さ | 26 px | 表示の文字サイズの 2 倍から 4 px を引く |
| 一致行の文字サイズ | 約 13 px | 表示の文字サイズの 0.87 倍 |
| 件数表示の文字サイズ | 12 px | 表示の文字サイズの 0.8 倍 |
| 一覧の上の余白 | 4 px | 固定 |
| 境界バーの高さ | 9 px | 固定。中央に幅 32 px、高さ 3 px の横棒を描く |

行の高さは整数の px にし、一覧の上の余白はスクロールする領域の外に置く。行の高さに端数があったり、スクロールする領域の内側に余白があったりすると、↑↓ で選択を動かしたときに行の位置がわずかにずれるためである。

### 4.3 検索欄が空のときの一覧

検索欄が空のときの一覧は、行の高さの決め方と件数表示を除いて、現行から変えない。すべてのノートをノート行として並べる。

- 順序は、ピン留めしたノート（利用者が決めた順）、その他のノート（更新の新しい順）とする。
- ノート行には、左から順に、並べ替えのつまみ、ノート名、⌘ と数字のキー表示、ピン留めのボタン、ゴミ箱のボタンを置く。2 つのボタンは、ポインタの位置にかかわらず常に表示する。
- ノート行の高さは、表示の文字サイズの 2 倍とする。現行は、行の中身に上下 5 px の余白を足した高さであり、高さを指定していない。
- 並べるノート行は 200 件までとする。
- 検索欄の右端に、一覧に並んでいるノートの数を「12 notes」の形で表示する。

### 4.4 検索

検索では、検索欄の入力を検索語に分け、すべての検索語を持つノートを探す。入力が変わるたびに結果を作り直し、一覧の先頭の行を選ぶ。

検索欄の入力を空白で区切り、それぞれを検索語とする。日本語入力で入る全角の空白でも区切る。検索語、ノート名、本文のいずれでも、次の文字を同じものとして扱う。

- 大文字と小文字
- 全角と半角の英数字・記号（「ＡＰＩ」と「api」）
- 全角と半角の空白

この扱いで 1 文字が 2 文字になることはない。そのため、見つけた位置は、そのまま元の本文の位置として使える。

ノート名と本文では、一致の判定が異なる。この区別は現行と同じである。

- ノート名は、あいまい一致で判定する。検索語がノート名に連続して含まれていれば、その箇所を一致とする。連続する箇所が複数あれば、語頭にあるものを優先する。連続して含まれていなくても、検索語の文字が順に含まれていれば一致とする。
- 本文は、部分一致で判定する。検索語がそのまま含まれる箇所を、すべて一致とする。

ノートは、すべての検索語がノート名か本文のどちらかに一致するときに、結果に入る。一致する場所は、検索語ごとに違ってよい。たとえば「会議 予算」は、ノート名に「会議」、本文に「予算」を持つノートに一致する。すべての検索語を求めるのは、検索語を足すほど結果を絞れるようにするためである。Obsidian の検索も、空白で区切った語をすべて含むファイルを返す（出典は末尾）。

結果のノートは、ノート名で一致したものを先に並べる。順序の規則を表 5 に示す。順が決まらないノートどうしは、検索欄が空のときの順（§4.3）を保つ。

表5：結果のノートの並び順

| 順位 | 条件 | 同じ条件の中での順 |
|---|---|---|
| 1 | すべての検索語がノート名に一致する | ノート名の一致の点数の合計が高い順 |
| 2 | 順位 1 以外 | ノート名に連続して含まれる検索語の数が多い順 |

ノート名の一致の点数は、検索語の 1 文字ごとに次の点を足し、ノート名の文字数の 0.01 倍を引いた値とする。文字数を引くのは、同じ一致なら短いノート名を先に並べるためである。

- 直前の文字に続けて一致した文字は 5 点
- 語頭で一致した文字は 3 点。語頭とは、ノート名の先頭か、空白・`-`・`_`・`.`・`/` の直後をいう
- そのほかの文字は 1 点

一覧に出す量には、上限を置く。結果のノートは 200 件までとする（現行と同じ）。一覧の行が 500 行に達したら、その次のノートからは並べず、検索語を足して結果が減るまで表示しない。検索欄の右端の件数表示は、検索中は結果のノートの数を示す。

### 4.5 検索結果の表示

検索中の一覧は、結果のノートごとに、見出しと、その下の一致行で構成する。VS Code の検索結果と同じ形である（図 1）。

- 見出しには、ノート名の全体を表示する。幅に収まらないときだけ、末尾を省略する。
- 一致行は、検索語を 1 つ以上含む本文の行ごとに、1 つ作る。本文の 1 行に一致が複数あっても、一致行は 1 つである。
- 結果のノートの一致行は、ノートごとの件数を絞らずに、最初からすべて並べる。
- ↑↓ で選べるのは一致行であり、一致行を持つノートの見出しは飛ばす。

一致行を持たないノートは、見出しそのものをノート行として選べるようにする。一致行を持たないのは、ノート名だけで一致して本文に検索語がない場合と、本文の一致がノート名と同じ内容の 1 行目にしかない場合である。

本文の 1 行目がノート名と同じ文字列のとき、1 行目は一致行にしない。ノート名は 1 行目から付くので、見出しと同じ内容の行が続けて並ぶのを避けるためである。同じかどうかは、見出しの `#` など行頭の記号を除いて比べる。

一致行には、本文のその行を 1 行で表示する。文面は次の手順で作る。

1. 行頭のインデント、箇条書きと引用の記号、見出しの `#`、表の行頭の `|` を除く。
2. 行の最初の一致が幅 48 より後ろで終わるときは、行の途中から表示し、先頭に「…」を付ける。表示は、一致の 8 文字前から一致までの間にある最初の空白の直後から始める。空白がなければ、一致の 8 文字前から始める。
3. 文面は 120 文字までとする。一覧の幅に収まらない分は、末尾を省略する。

手順 2 の幅は、半角の 1 文字を 1、日本語などの全角の 1 文字を 2 として数える。48 は、既定の幅のパネルで一致行に収まるおよその幅である。

一致した文字は、本文色にして、太さ 2 px の黄色の下線を引く。太字にはしない。黄色は、ノート内検索が現在の一致に使う色と同じである。

- 一致行では、文面にあるすべての検索語の一致に印を付ける。
- 見出しでは、ノート名に連続して含まれる検索語に印を付ける。
- 文字が離れたあいまい一致の印は、すべての検索語がノート名に一致したノートの見出しにだけ付ける。本文で一致したノートの名前に、偶然順に並んだ文字へ印が付くのを避けるためである。

見た目は、次のように決める。

- 見出しは、検索欄が空のときのノート名と同じ左位置、同じ文字サイズで表示する。
- 一致行は、左に縦の罫線を引き、見出しより小さい文字と薄い色で表示する（表 4）。
- 検索中は、つまみ、キー表示、ピン留めのボタン、ゴミ箱のボタンを表示しない。ゴミ箱へ移す操作は、検索中も ⌘⌫ で行える。
- 一致行を選んで一覧がスクロールするときは、一致行の上に 1 行分の余裕を残す。上へ移動したときに、そのノートの見出しが見えるようにするためである。
- 結果のノートがないときは、一覧に「No notes match」と表示する。

### 4.6 プレビュー

プレビューには、選択中の行のノートを、エディタと同じ見た目で表示する。Enter で開くものを、開く前に確かめられるようにするためである。

- エディタと同じフォント、折り返し、Markdown の色付けで表示する。編集はできない。フォーカスは検索欄に置いたままにする。
- ノート行を選んでいるときは、ノートを先頭から表示する。
- 一致行を選んでいるときは、その行を、プレビューの上端から 1 行下に置く。
- 結果のノートがないときは、開いているノートを表示する。
- プレビューをクリックすると、クリックした位置でノートを開く（§4.7）。

ノートごとの前回のカーソル位置やスクロール位置は使わない。行を移るたびに表示位置がばらつくのを避けるためである。一致行を上端の近くに置くのは、ノートを開いた後も一致が見えるようにするためである。開いた後は、ノート内検索のバーがパネルの下端に出る。

一致を持つ行を選んでいるときは、そのノートの本文にあるすべての一致に印を付ける。印はノート内検索と同じものを使い、選択中の行が開く一致には「現在の一致」と同じ濃い黄色を、そのほかの一致には薄い黄色を敷く。ノートを開くとノート内検索が同じ箇所に同じ印を付けるので、開く前と後で見た目が変わらない。

### 4.7 ノートを開く

行を開くと、切替画面を閉じ、プレビューで見えていた位置のままノートを表示する。一致を持つ行から開いた場合は、その検索語でノート内検索を始める。開く対象と、開いた後の状態の対応を表 6 に示す。見出しのクリックは、そのノートの最初の一致行を開くのと同じである。

表6：開く対象と、開いた後の状態

| 開く対象 | 選択とカーソル | ノート内検索 |
|---|---|---|
| 一致行 | その行の最初の一致を選択する | その一致の検索語で開く |
| ノート行（1 行目に本文の一致がある） | 1 行目の最初の一致を選択する | その一致の検索語で開く |
| ノート行（本文に一致がない。検索欄が空の場合を含む） | カーソルを前回の位置のままにする | 開かない |
| プレビューのクリック位置 | カーソルをクリックした位置に置く | 選択中の行に一致があれば、最初の検索語で開く |

ノート内検索については、次のように定める。

- ノート内検索に渡す検索語は 1 つとする。ノート内検索は 1 つの文字列しか探せないためである。複数の検索語で探した場合も、開いた一致の検索語だけを渡す。
- 検索語は、正規表現ではなく、文字列そのままとして渡す。
- フォーカスは、ノート内検索のバーではなくノートに置く。そのまま ⌘G と ⇧⌘G で、次と前の一致へ移れる。
- 一覧を作った後にノートが書き換わり、覚えていた位置の文字列が検索語と違う場合は、ノートの最初の一致を選択する。
- このノート内検索は、次に切替画面を開くときの検索欄の初期値にしない（§4.1）。

開いた後の本文は、プレビューで見えていた位置に表示する。プレビューの先頭に見えていた行が、開いた後も同じ高さに来るようにスクロールする。開く前と後で本文が動かないので、見ていた箇所を見失わない。検索欄が空のときにノート行を開いた場合も同じで、ノートは先頭から表示し、カーソルは前回の位置に残す。次の場合は、表示位置を調整する。

- ノート内検索のバーが、選択した一致やクリック位置を覆う場合は、覆う分だけ本文を上へずらす。
- 開く箇所がプレビューに見えていない場合は、一致を画面の中央に置く。プレビューの高さが 0 の場合や、選択中の行とは別のノートの行をクリックした場合がこれに当たる。中央に置く動作は現行と同じである。

ノートを開く処理は、次の順に進む。開く位置は JS が覚えておき、Swift には渡さない。

1. 利用者が行を開く。JS は、開く位置、検索語、プレビューの表示位置を覚え、Swift に `select` を送る。
2. Swift はノートを開き、JS に `open` を送る。
3. JS はノートを表示して切替画面を閉じ、覚えていた内容で選択、ノート内検索、表示位置を設定する。

### 4.8 検索履歴

前に検索した入力は、先頭の行で ↑ を押すとさかのぼれる。VS Code の検索欄と同じキーである。

- 切替画面を閉じたとき、検索欄が空でなければ、その入力を検索履歴に加える。閉じ方（行を開く、Esc、⌘P）は問わない。
- 同じ入力がすでに検索履歴にあれば、古いほうを消す。検索履歴は 50 件までとし、アプリを終了すると消える。
- 先頭の行を選んでいるときに ↑ を押すと、1 つ前の入力を検索欄に入れて全選択し、その入力で検索する。続けて ↑ を押すと、さらに前の入力にさかのぼる。
- 検索欄と同じ入力は飛ばす。いちばん古い入力まで来たら、それ以上は動かない。
- 文字を入力すると、さかのぼりは最新の入力からやり直しになる。

現行では、先頭の行で ↑ を押しても何も起きない。そのため、検索履歴は既存の操作と重ならない。

↓ は、検索履歴には使わず、常に次の行へ移る。VS Code では ↓ で新しい入力へ戻れるが、切替画面の ↓ は行の移動に使っている。↓ を検索履歴にも使うと、さかのぼった入力の結果の 2 行目以降へ、キーで移れなくなる。新しい入力へ戻るときは、入力し直す。← と → も使わない。検索欄のカーソルの移動に使うキーであり、さかのぼった入力を直して使えなくなるためである。

### 4.9 操作の一覧

キーの割り当ては現行から変えない。加えるキーの操作は、先頭の行で ↑ を押したときの検索履歴だけである。マウスの操作は、見出し、プレビュー、境界バーに対する 3 つを加える。操作の一覧を表 7 に示す。

表7：切替画面の操作

| 操作 | 動作 | 現行との違い |
|---|---|---|
| ↑ / ↓ | 前後の行を選ぶ。↓ は一覧の末尾で止まる | 検索中は、一致行を持つノートの見出しを飛ばす |
| ↑（先頭の行を選んでいるとき） | 検索履歴を 1 つさかのぼる（§4.8） | 追加。現行では何も起きない |
| ↩ | 選択中の行を開く | 開いた後の状態が変わる（§4.7） |
| Esc | 切替画面を閉じる | ホットキーで出したパネルは、同時に隠す（§4.1） |
| ⌘P | 切替画面を閉じる | なし |
| ⌘⌫ | 選択中の行のノートを、確認してからゴミ箱へ移す | なし |
| ⌥↑ / ⌥↓ | ピン留めしたノートを上下へ移す。検索欄が空のときだけ使える | なし |
| ⌘A | 検索欄の文字列を全選択する | なし |
| ⌘1〜⌘9 | 1〜9 番目のピン留めしたノートを開く | なし |
| 行のクリック | その行を開く | なし |
| 見出しのクリック | そのノートの最初の一致行を開く | 追加 |
| プレビューのクリック | クリックした位置でノートを開く | 追加 |
| 境界バーのドラッグ | プレビューの高さを変える（§4.2） | 追加 |
| つまみのドラッグ | ピン留めしたノートを並べ替える。検索欄が空のときだけ使える | なし |
| ピン留めのボタンのクリック | ピン留めを切り替える | 検索中はボタンを表示しない |
| ゴミ箱のボタンのクリック | その行のノートを、確認してからゴミ箱へ移す | 検索中はボタンを表示しない |

日本語入力の変換中は、Enter、Esc、矢印キーを切替画面の操作に使わない（現行と同じ）。マウスで操作しても、フォーカスを検索欄から動かさない。クリックやドラッグの後も、そのまま入力を続けられる。

## 5. ブリッジのメッセージ

内容を変えるメッセージは `switcher`、`options`、`noteShare` の 3 つである。切替画面に関わるメッセージを表 8 に示す。

表8：切替画面に関わるメッセージ

| 向き | 名前 | 内容 | 変更 |
|---|---|---|---|
| Swift→JS | `switcher` | `{notes, force, dismiss}`：切替画面を開閉する。`dismiss` が真なら、Esc でパネルも隠す | `dismiss` を追加する |
| Swift→JS | `options` | `noteShare`：切替画面の高さに対する、プレビューの高さの割合（0〜1） | `noteShare` を追加する |
| JS→Swift | `noteShare` | `{share}`：境界バーのドラッグを終えたときに、新しい割合を送る | 新しく加える |
| JS→Swift | `escape` | パネルを隠す | メッセージは既存。切替画面からも送るようにする |
| JS→Swift | `select` | `{id}`：ノートを開く。開く位置は含めない | なし |
| Swift→JS | `open` | `{id, text, keep, opening}`：ノートを開く | メッセージは変えない。JS が、覚えていた位置を適用する（§4.7） |
| Swift→JS | `renamed` | `{from, to}`：ノート名の変更を伝える | メッセージは変えない。JS が、ノート内検索を始めたノートの名前も付け替える |
| Swift→JS | `notes` | 一覧を更新する | なし |
| JS→Swift | `trash`、`pin`、`orderPins` | ゴミ箱へ移す、ピン留めを切り替える、ピン留めの順を保存する | なし |

Swift 側の処理は、次の 2 つである。

- `PanelController.search()` は、パネルを表示する前にパネルが隠れていたかどうかを調べ、その真偽を `switcher` の `dismiss` に入れる。⌘P とタイトルバーの一覧ボタンから開くときは、`dismiss` を偽にする。メニューの「Search Notes」も `search()` を呼ぶので、ホットキーと同じ動作になる。
- `noteShare` を受け取ったら `UserDefaults` に保存する。保存した値は、ほかの設定と同じ経路（`applySettings` → `setOptions`）で `options` に入り、JS に届く。

JS 側は、値が届かない場合に備える。`dismiss` がなければ偽として扱う。`noteShare` がないか数値でなければ 0.4 を使い、0〜1 の範囲外の値は範囲内に丸める。

### 6.2 実装の方針

追加する機能は、既存の処理の内側に分岐として足さず、既存の経路の外側に置く。既存の操作は、変更の前と後で同じコードを通る。機能ごとの置き場所を表 10 に示す。

表10：機能ごとの置き場所

| 機能 | 置き場所 | 既存の処理への影響 |
|---|---|---|
| 検索欄が空のときの一覧 | 現行の行の描画（`row`）を、`noteRow` という名前でそのまま使う | なし。検索中の表示は別の関数 `group` に分け、`noteRow` に分岐を足さない |
| 一覧の組み立て | `update` の 1 か所で、結果のノートごとに `noteRow` か `group` を呼ぶ。選べる行は、描画する関数が `rows` に登録する | 行の種類を表すフラグや、並べた行をあとからノートごとにまとめ直す処理を持たない |
| プレビュー | エディタとは別の、読み取り専用の CodeMirror に表示する | エディタ本体には触れない。開いているノートの内容、取り消しの履歴、保存に使う番号（`opening`）は、切替画面を開いている間も変わらない |
| ノートを開く | 現行の `select` → `open` の往復をそのまま使う。選択、ノート内検索、表示位置は、`open` を受けた直後の 1 か所（`land`）で設定する | Swift の開く処理と `openNote` は変えない |
| ノート内検索 | CodeMirror の検索機能の状態を、エディタに最初から持たせる。`land` がそのパネルを開く | ⌘F の動作は変えない |
| 検索履歴の記録 | 切替画面を閉じる関数 `closeSwitcher` で記録する。閉じる経路は、すべてこの関数を通る | 個々の閉じ方（Enter、Esc、⌘P、クリック）の処理には手を入れない |
| 検索履歴のさかのぼり | 先頭の行で ↑ を押したときだけ動く。現行では何も起きない操作である | ↑↓ による行の移動は変えない |
| Esc でパネルを隠す | 隠すかどうかは、パネルの状態を知っている Swift の `search()` が決め、`dismiss` で渡す。JS は、Esc のときに既存の `escape` を送る | Swift の `escape` の処理と、エディタでの Esc は変えない |
| プレビューの高さの保存 | 既存の設定の経路に載せる。Swift は値を `UserDefaults` に書くだけである | 保存と配布のための新しい仕組みを作らない |

プレビューについては、選択中の行のノートをエディタ本体に一時的に表示する方式も検討した。VS Code のプレビューと同じ形で、別のビューが要らず、開いた後の表示位置も合わせやすい。この方式は採らない。開いているノートの状態を退避して戻す処理がエディタ本体に入り、戻し損ねるとノートを編集できなくなるためである。

### 6.3 意図した簡略化

次の 3 点は、コードを小さく保つために簡略にしている。コードには `// shortcut:` のコメントで記してある。

- 入力のたびに、全ノートの本文へ同一視の変換（§4.4）をかける。4 kB のノート 500 件で約 8 ms かかる。入力が遅れるようになったら、変換した本文を保持する。
- 一覧は、500 行に達したノートで打ち切る（§4.4）。
- 検索履歴は JS が持ち、アプリを終了すると消える（§4.8）。残すには、Swift に送って保存する。

| 呼び出し | ⇧↩ で、入力した名前のノートを新しく作る | 説明が要る機能であり、必要がない |

| 画面の構成 | 切替画面を別のウインドウにする | パネルに重ねて表示する現行の形を保つ |
| 画面の構成 | 切替画面を開くときに、パネルの大きさを自動で変える | パネルの大きさは、利用者が変えない限り保つ（`docs/design.md` §5.2） |

| 一覧 | ピン留めとゴミ箱のボタンを、ポインタを載せた行にだけ表示する | 常に表示する現行の動作を、変える必要がない |
| 一覧 | 開いているノートの行に「current」と表示する | 必要がない |
| 検索 | いずれかの検索語を含むノートを結果にする | 検索語を足すと結果が増え、絞り込めない（§4.4） |
| 検索結果の表示 | ノートごとに一致の件数を表示し、切替画面の中で ⌘G により次の一致へ移る | 一致行を最初からすべて並べるので、必要がない |
| 検索結果の表示 | 一致箇所を太字にする | 下線で足りる |
| 検索結果の表示 | ノート名を左の列、一致行の文面を右の列に並べる | 同じノートの 2 行目以降で、左の列が空白になる。列の幅を固定すると広すぎることが多く、狭くするとノート名が切れる |
| 検索結果の表示 | ノート名で一致したノートは、ノート名だけの行にする | 行の右側が空いて無駄になる。本文の一致も、ほかのノートと同じ形で表示する |
| 検索結果の表示 | スクロール中も、ノートの見出しを一覧の上端に固定する | 見出しと下の行の文字が重なり、見た目が悪い。一致行の上に 1 行分の余裕を残す方法（§4.5）に替えた |
| プレビュー | ノートを、前回のカーソル位置から表示する | 行を移るたびに表示位置がばらつく（§4.6） |

## 9. 既知の制約と未確認の項目

画面の動作は、ヘッドレスの Chrome でしか確かめていない。アプリが使う WKWebView とは、フォントと文字の描画が違う。実機では、次の点を確かめる。

- 一致箇所の下線が、英字だけの行でも日本語の行でも欠けずに表示される。
- プレビューの高さを最大にした状態で ↑↓ を押しても、一覧の行が上下にずれない。
- 行を開いたとき、本文がプレビューと同じ位置に表示され、ノート内検索のバーが一致を覆わない。
- 日本語入力の変換中に、Enter、Esc、矢印キーが切替画面の操作にならない。
- 境界バーのドラッグが、パネルの移動や大きさの変更と競合しない。
- 検索のホットキーで隠れていたパネルを出し、Esc を押すと、切替画面とパネルの両方が閉じる。
- プレビューの高さが、アプリを起動し直した後も残る。

既知の制約は、次のとおりである。

- ノート内検索は全角と半角を区別する。本文の全角の「ＡＰＩ」は、切替画面では「api」で見つかり、プレビューで印が付く。開いた後は、その一致を選択するが、ノート内検索の印は付かない。
- ノート内検索のバーは、CodeMirror の既定の見た目のままである。幅の狭いパネルでは、高さが 90 px ほどになる。
