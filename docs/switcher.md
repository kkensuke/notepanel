## 1. 目的と範囲

切替画面（ノートを探して開く画面）を、ノートに重ねず、パネルの外側の左に、別のウインドウとして出す。一覧で行を選ぶと、その行のノートを横のパネルに表示する。ノートの中の検索も切替画面で行い、エディタの検索パネルはなくす。

設計では、次の 4 点を方針とした。

- 何を呼び出したときに、どこにフォーカスがあるかを単純に決める。ノートを切り替えるときは一覧に、検索するときは検索欄に置く。
- コードの変更を小さくする。
- 説明がないと使えない機能を加えない。
- 行の高さと余白をそろえ、見た目を整える。

対象は、切替画面の呼び出しから、選んだノートを表示して切替画面を閉じるまでである。⌘Y で開く以前の版の画面は対象外とする。

## 4. 仕様

### 4.1 呼び出しと閉じ方

切替画面を開く操作は、表 3 の 4 つである。⌘P と ⌘F は、押すたびに開閉を切り替える。ただし、フォーカスがそのキーの置く場所になければ、閉じずにフォーカスをそこへ移す。

表3：切替画面を開く操作

| 操作 | 切替画面が閉じているとき | 切替画面が開いているとき |
|---|---|---|
| ⌘P（パネル内） | 開いて、一覧にフォーカスを置く | フォーカスが一覧にあれば閉じる。なければ、一覧にフォーカスを移す |
| ⌘F（パネル内） | 開いて、検索欄にフォーカスを置く | フォーカスが検索欄にあれば閉じる。なければ、検索欄にフォーカスを移し、入力を全選択する |
| タイトルバーの一覧ボタン | 開いて、一覧にフォーカスを置く | フォーカスの位置にかかわらず閉じる |
| メニューの「Search Notes」と、Search notes のホットキー | パネルを表示して開き、検索欄にフォーカスを置く | 閉じずに、検索欄にフォーカスを移し、入力を全選択する |

開いた直後は、検索欄を空にし、開いているノートの行を選ぶ。⌘P で開いたときは、そのまま ↑↓ でノートを移れる。切替画面を使うのは、検索するときよりも、別のノートを開くときのほうが多いためである。

ノートで文字列を選択してから ⌘F を押すと、その文字列で検索する。動作は、その文字列を検索欄に入力して ↩ を押したとき（§4.6）と同じにする。検索欄にその文字列が入り、フォーカスは一覧の先頭の行に移る。次の場合は、選択を使わずに、表 3 のとおりに動く。

- 選択が複数の行にまたがる。
- 選択が空白だけである。
- 選択が、切替画面の検索が残したものである（§4.6）。検索を終えた直後の ⌘F を、新しい検索として始められるようにするためである。
- フォーカスがノートにない。

切替画面を閉じる操作は、次のとおりである。閉じると、フォーカスをノートに戻す。表示しているノートは、閉じた後もそのまま開いている。

- 表 3 の操作で閉じる。
- 切替画面で Esc を押す。ホットキーかメニューの「Search Notes」で、隠れていたパネルを出して切替画面を開いた場合は、Esc の 1 回で切替画面を閉じ、パネルも隠す。
- 切替画面を開いたままノートにフォーカスを移し、ノートで Esc を押す。
- 一覧で ↩ を押すか、行をダブルクリックする（§4.6）。
- 切替画面の外の操作でノートを開く（⌘N、⌘1〜⌘9）。

フッターにメッセージが出ても、切替画面は閉じない。切替画面はフッターを隠さないためである。

切替画面は、パネルのほかの機能と同時に使える。どれも、切替画面がパネルの外の別のウインドウにあるので、互いに重ならない。

- **以前の版の画面（⌘Y）。** 切替画面を開いても、以前の版の画面は閉じない。切替画面を開いたまま ⌘Y を押すと、パネルにフォーカスを移して以前の版の画面を開く。一覧で別のノートを表示すると、以前の版の画面は閉じる。別のノートを開くほかの操作と同じである。
- **⌃Tab と ⌃⇧Tab。** 切替画面を開いたまま、前後のノートへ移れる。開いたノートは一覧でも選ぶ（§4.6）。
- **⌃⌘M。** 切替画面を開いたまま、パネルを既定の位置と大きさに移せる。切替画面はパネルに付いて動く。

### 4.2 画面の構成

切替画面は、パネルの外側の左に、別のウインドウとして出す。上から順に、検索欄と一覧で構成する。検索中の構成を図 1 に示す。

```
                       ┌───────────────────────────────────┐
                       │ o o [=]    Weekly plan    [+] [/] │  タイトルバー
┌──────────────────────┼───────────────────────────────────┤
│ Q api        6 notes │ # Weekly plan                     │
├──────────────────────┤                                   │
│ Weekly plan          │ - [x] Send the final slides       │
│ │ Review the API d...│ - [ ] Review the API design notes │
│ API design notes     │                                   │
│ │ One API for the ...│ ## Ideas                          │
│ │ Keep the API sma...│                   213 characters  │
└──────────────────────┴───────────────────────────────────┘
```

図1：検索中の切替画面。左が切替画面のウインドウ（検索欄と一覧）、右がパネル（タイトルバーとノート）。タイトルバーの左端の `[=]` が一覧ボタンである

切替画面のウインドウは、次のように出す。

- パネルの左に、すき間なく付けて出す。上端はタイトルバーの下にそろえる。高さは、検索欄の下にノート行がちょうど 10 行見える高さまでとし、パネルのほうが低ければ、パネルの下端までとする。パネルとタイトルバーは、位置も大きさも変えない。そのため、一覧ボタンは開いても閉じても同じ位置にあり、同じ位置を押せば開閉できる。
- パネルの子ウインドウにする。パネルを動かすと一緒に動き、パネルの大きさを変えると高さが追従する。パネルを隠すと一緒に隠れ、パネルを出すと一緒に出る。
- 背景は、パネルと同じガラスとスクリムにする。設定の背景の不透明度にも従う。
- 角は、行の角の半径（6 px）に縁の 1 px を足した 7 px で丸める。こうすると、選択中の行の枠が、下の角で欠けない。
- 影は付けない。切替画面のウインドウがキーウインドウになると、影が角の丸みに沿わず、ウインドウの四角い枠に沿って付くためである。
- 幅は、既定を 220 pt、最小を 140 pt とする。切替画面の左端をドラッグすると、幅が変わる。ディスプレイの左端より外へは広げない。幅は、閉じたときに保存する。
- ディスプレイの左端までの距離が切替画面の幅より短いときは、開いている間、足りない分だけパネルを右へ動かす。閉じるときに、パネルがその位置のままなら、元の位置へ戻す。

切替画面は、次のように作る。

- 検索欄は、入力欄に枠を付けず、左に虫眼鏡のアイコン、右端に件数表示を置く。検索欄と一覧の間には、細い罫線を引く。
- 一覧は検索欄の下に置き、切替画面の下端まで使う。行が収まらないときは、一覧だけをスクロールする。
- 行は、切替画面の左端から右端まで届く。一覧の左右、上、下に余白を置かない。
- 一覧にフォーカスがあるときは、選択中の行にアクセント色の枠（太さ 1.5 px）を付ける。フォーカスがどこにあるかを示すためである。
- 切替画面の縁には、細い線を引く。

各部の寸法を表 4 に示す。px の値は、表示の文字サイズが既定の 15 px の場合である。

表4：各部の寸法（表示の文字サイズが 15 px の場合）

| 部分 | 寸法 | 決め方 |
|---|---|---|
| 切替画面の幅 | 220 pt | 既定。切替画面の左端のドラッグで変えられる。最小は 140 pt |
| 切替画面の角の半径 | 7 px | 行の角の半径に、縁の 1 px を足す |
| 切替画面の高さ | 最大で、検索欄 + 300 px + 2 px | ノート行 10 行と、上下の縁。パネルのほうが低ければパネルに合わせる |
| ノート行の高さ（検索欄が空のとき） | 30 px | 表示の文字サイズの 2 倍 |
| 見出しと一致行の高さ | 26 px | 表示の文字サイズの 2 倍から 4 px を引く |
| 一致行の文字サイズ | 約 13 px | 表示の文字サイズの 0.87 倍 |
| 件数表示の文字サイズ | 12 px | 表示の文字サイズの 0.8 倍 |
| 行の左右の内側の余白 | 8 px | 固定。検索欄のアイコンと、ノート名の左位置をそろえる |
| 行の角の半径 | 6 px | 固定 |

行の高さは整数の px にする。端数があると、↑↓ で選択を動かしたときに行の位置がわずかにずれるためである。

### 4.3 検索欄が空のときの一覧

検索欄が空のときは、すべてのノートをノート行として並べる。

- 順序は、ピン留めしたノート（利用者が決めた順）、その他のノート（更新の新しい順）とする。
- ノート行には、左から順に、ノート名、⌘ と数字のキー表示、ピン留めのボタン、ゴミ箱のボタンを置く。2 つのボタンは、ポインタの位置にかかわらず常に表示する。
- キー表示は、1〜9 番目のピン留めに付ける。キー表示をドラッグすると、ピン留めしたノートを並べ替えられる。並べ替え専用のつまみを置かないのは、その幅をノート名に使うためである。
- 並べるノート行は 200 件までとする。
- 検索欄の右端に、一覧に並んでいるノートの数を「12 notes」の形で表示する。

### 4.4 検索

検索では、検索欄の入力を検索語に分け、すべての検索語を持つノートを探す。入力が変わるたびに結果を作り直し、一覧の先頭の行を選ぶ。開いているノートが結果にあれば、その本文の一致に印を付ける（§4.6）。

検索欄の入力を空白で区切り、それぞれを検索語とする。日本語入力で入る全角の空白でも区切る。検索語、ノート名、本文のいずれでも、次の文字を同じものとして扱う。

- 大文字と小文字
- 全角と半角の英数字・記号（「ＡＰＩ」と「api」）
- 全角と半角の空白

この扱いで 1 文字が 2 文字になることはない。そのため、見つけた位置は、そのまま元の本文の位置として使える。

ノート名と本文では、一致の判定が異なる。

- ノート名は、あいまい一致で判定する。検索語がノート名に連続して含まれていれば、その箇所を一致とする。連続する箇所が複数あれば、語頭にあるものを優先する。連続して含まれていなくても、検索語の文字が順に含まれていれば一致とする。
- 本文は、部分一致で判定する。検索語がそのまま含まれる箇所を、すべて一致とする。

ノートは、すべての検索語がノート名か本文のどちらかに一致するときに、結果に入る。一致する場所は、検索語ごとに違ってよい。たとえば「会議 予算」は、ノート名に「会議」、本文に「予算」を持つノートに一致する。すべての検索語を求めるのは、検索語を足すほど結果を絞れるようにするためである。Obsidian の検索も、空白で区切った語をすべて含むファイルを返す（出典は末尾）。

結果のノートは、起点のノートを先頭に置く。1 つのノートの中を探すときに、そのノートの一致行が一覧の先頭に来るようにするためである。残りのノートは、ノート名で一致したものを先に並べる。順序の規則を表 5 に示す。順が決まらないノートどうしは、検索欄が空のときの順（§4.3）を保つ。

表5：結果のノートの並び順

| 順位 | 条件 | 同じ条件の中での順 |
|---|---|---|
| 1 | 起点のノートである | 1 件だけである |
| 2 | すべての検索語がノート名に一致する | ノート名の一致の点数の合計が高い順 |
| 3 | 順位 1、2 以外 | ノート名に連続して含まれる検索語の数が多い順 |

ノートで文字列を選択して ⌘F を押したとき（§4.1）は、そのときに開いているノートを起点のノートにする。

ノート名の一致の点数は、検索語の 1 文字ごとに次の点を足し、ノート名の文字数の 0.01 倍を引いた値とする。文字数を引くのは、同じ一致なら短いノート名を先に並べるためである。

- 直前の文字に続けて一致した文字は 5 点
- 語頭で一致した文字は 3 点。語頭とは、ノート名の先頭か、空白・`-`・`_`・`.`・`/` の直後をいう
- そのほかの文字は 1 点

一覧に出す量には、上限を置く。結果のノートは 200 件までとする。一覧の行が 500 行に達したら、その次のノートからは並べず、検索語を足して結果が減るまで表示しない。検索欄の右端の件数表示は、検索中は結果のノートの数を示す。

### 4.5 検索結果の表示

検索中の一覧は、結果のノートごとに、見出しと、その下の一致行で構成する。VS Code の検索結果と同じ形である（図 1）。

- 見出しには、ノート名の全体を表示する。幅に収まらないときだけ、末尾を省略する。
- 一致行は、本文の一致ごとに 1 つ作る。本文の 1 行に一致が複数あれば、その行の一致行を一致の数だけ並べる（VS Code と同じ）。↑↓ で、同じ行の一致も 1 つずつたどれるようにするためである。
- ただし、ほかの一致の中にある一致は、一致行にしない。検索語の一方が他方を含むとき（`foo o` の `o` など）や、同じ検索語を 2 回入力したときに、同じ文面の行が重ねて並ぶのを避けるためである。
- 結果のノートの一致行は、ノートごとの件数を絞らずに、最初からすべて並べる。
- ↑↓ で選べるのは一致行であり、一致行を持つノートの見出しは飛ばす。

一致行を持たないノートは、見出しそのものをノート行として選べるようにする。一致行を持たないのは、ノート名だけで一致して本文に検索語がない場合と、本文の一致がノート名と同じ内容の 1 行目にしかない場合である。

本文の 1 行目がノート名と同じ文字列のとき、1 行目は一致行にしない。ノート名は 1 行目から付くので、見出しと同じ内容の行が続けて並ぶのを避けるためである。同じかどうかは、見出しの `#` など行頭の記号を除いて比べる。

一致行には、本文のその行を 1 行で表示する。文面は次の手順で作る。

1. 行頭のインデント、箇条書きと引用の記号、見出しの `#`、表の行頭の `|` を除く。
2. その一致行の一致が幅 48 より後ろで終わるときは、行の途中から表示し、先頭に「…」を付ける。表示は、一致の 8 文字前から一致までの間にある最初の空白の直後から始める。空白がなければ、一致の 8 文字前から始める。
3. 文面は 120 文字までとする。一覧の幅に収まらない分は、末尾を省略する。

手順 2 の幅は、半角の 1 文字を 1、日本語などの全角の 1 文字を 2 として数える。

一致した文字は、本文色にして、太さ 2 px の黄色の下線を引く。太字にはしない。黄色は、ノートの印のうち、濃いほうと同じ色である。

- 一致行では、その一致行の一致にだけ下線を引く。同じ行の一致行どうしを、どの一致の行か見分けられるようにするためである。
- 見出しでは、ノート名に連続して含まれる検索語に下線を引く。
- 文字が離れたあいまい一致の下線は、すべての検索語がノート名に一致したノートの見出しにだけ引く。本文で一致したノートの名前に、偶然順に並んだ文字へ下線が付くのを避けるためである。

見た目は、次のように決める。

- 見出しは、検索欄が空のときのノート名と同じ左位置、同じ文字サイズで表示する。
- 一致行は、左に縦の罫線を引き、見出しより小さい文字と薄い色で表示する（表 4）。
- 検索中は、キー表示、ピン留めのボタン、ゴミ箱のボタンを表示しない。ゴミ箱へ移す操作は、検索中も ⌘⌫ で行える。
- 一致行を選んで一覧がスクロールするときは、一致行の上に 1 行分の余裕を残す。上へ移動したときに、そのノートの見出しが見えるようにするためである。
- 結果のノートがないときは、一覧に「No notes match」と表示する。

### 4.6 行の選択とノートの表示

検索欄と一覧は、それぞれがフォーカスを持つ。↑↓ では、両者の間を移らない。検索欄の ↑↓ を検索履歴（§4.7）に使うためである。両者の間は、Tab、⌘P、⌘F で移る。

一覧にフォーカスがあるときは、選択中の行のノートを、切替画面の横に表示する。

- ↑↓ で前後の行を選ぶと、その行のノートを表示する。
- 行をクリックすると、一覧にフォーカスを移してその行を選び、ノートを表示する。見出しのクリックは、そのノートの最初の一致行のクリックと同じである。
- ↩ を押すと、選択中の行のノートを開いたまま、切替画面を閉じる。行のダブルクリックも同じである。

検索欄で ↩ を押すと、一覧の先頭の行へフォーカスを移し、その行のノートを表示する。続けて ↑↓ で、一致行を順にたどれる。起点のノートが結果にあれば、先頭の行は起点のノートの最初の一致行である（§4.4）。

ノートの表示は、ノートを実際に開く操作である。タイトルバーのノート名も、そのノートに変わる。そのため、Esc で切替画面を閉じても、起点のノートには戻らない。プレビュー用の別の表示を持たないのは、開いているノートの状態を退避して戻す処理を、エディタに入れないためである。

行の種類と、表示した後のノートの状態の対応を表 6 に示す。

表6：行の種類と、表示した後のノートの状態

| 行の種類 | 選択とカーソル | 表示位置 | 印 |
|---|---|---|---|
| 一致行 | その一致行の一致を選択する | 一致を画面の中央に置く | 本文のすべての一致に付ける |
| ノート行（1 行目に本文の一致がある） | 1 行目の最初の一致を選択する | 一致を画面の中央に置く | 本文のすべての一致に付ける |
| ノート行（本文に一致がない。検索欄が空の場合を含む） | カーソルを前回の位置のままにする | 前回の位置のままにする | 付けない |

印については、次のように定める。

- 印は 2 種類とする。一覧で選んだ一致には濃い黄色を、そのほかの一致には薄い黄色を敷く。
- 検索欄に入力している間は、開いているノートの一致に、薄い黄色の印を付ける。入力が変わるたびに付け直す。切替画面が、1 つのノートの中の検索を兼ねるためである。
- 印は、ノートのページが、開いているノートの今の本文を検索語で探して付ける。一覧を作った後にノートが書き換わっても、今の本文の一致に付く。
- 印は、ノートを書き換えたとき、別のノートを表示したとき、切替画面を閉じたときに消す。

一致の選択は、切替画面を閉じた後も残す。そのまま入力すると、一致を置き換えられる。この選択は、次に ⌘F を押したときの検索語にはしない（§4.1）。

一覧を作った後にノートが書き換わり、覚えていた位置の文字列が検索語と違う場合は、ノートの最初の一致を選択する。

ノートを表示する処理は、次の順に進む。切替画面のページとノートのページは、Swift を介してやり取りする。

1. 利用者が行を選ぶ。切替画面のページは、Swift に `select` を送る。`select` には、ノートの名前と、置く位置（`land`：検索欄の入力と、行の一致の位置）を入れる。
2. Swift はノートを開き、ノートのページに `open` を送る。`open` には、受け取った `land` をそのまま入れる。
3. ノートのページはノートを表示し、`land` に従って選択、表示位置、印を設定する。

検索欄の入力が変わるたびに、切替画面のページは `marks` で入力を Swift に送る。Swift はそれをノートのページに渡し、ノートのページが印を付け直す。

一覧の外の操作で、切替画面を開いたままノートが開いたとき（⌃Tab、開いているノートをゴミ箱へ移したとき）は、Swift が切替画面のページに `current` でそのノートを伝える。切替画面のページは、そのノートの最初の行を選び、検索中ならそのノートに印を付ける。一覧の選択と、表示しているノートが食い違わないようにするためである。

### 4.7 検索履歴

前に検索した入力は、検索欄で ↑↓ を押すとたどれる。VS Code の検索欄と同じキーである。

- 検索に使った入力を、検索履歴に加える。使ったとは、その入力の結果から行を選んでノートを表示したことをいう。切替画面を閉じたときに検索欄が空でなければ、その入力も加える。
- 同じ入力がすでに検索履歴にあれば、古いほうを消す。検索履歴は 50 件までとし、アプリを終了すると消える。
- 検索欄で ↑ を押すと、1 つ前の入力を検索欄に入れて全選択し、その入力で検索する。続けて ↑ を押すと、さらに前の入力にさかのぼる。
- ↓ を押すと、新しい入力のほうへ戻る。最後は、さかのぼる前に検索欄にあった入力に戻る。
- 検索欄と同じ入力は飛ばす。いちばん古い入力まで来たら、それ以上は動かない。
- 文字を入力すると、さかのぼりは最新の入力からやり直しになる。

← と → は使わない。検索欄のカーソルの移動に使うキーであり、さかのぼった入力を直して使えなくなるためである。

切替画面のキーの操作を表 7 に示す。↑↓、↩、Tab の動作は、フォーカスが検索欄にあるか一覧にあるかで変わる。

表7：切替画面のキーの操作

| キー | フォーカスが検索欄にあるとき | フォーカスが一覧にあるとき |

| ↑ / ↓ | 検索履歴を前 / 後へたどる（§4.7） | 前後の行を選び、その行のノートを表示する（§4.6） |
| ↩ | 一覧の先頭の行へフォーカスを移し、その行のノートを表示する | 選択中の行のノートを開いたまま、切替画面を閉じる |

表8：切替画面のマウスの操作

ノートのページと切替画面のページは、それぞれ自分の `EditorBridge` を持つ。2 つのページは直接やり取りせず、Swift が中継する。切替画面に関わるメッセージを表 9 に示す。「ページ」の列は、Swift とやり取りする側のページである。現行から、`switcher` の内容を変え、`switcherShown`、`marks`、`close`、`current`、`side`、`sideWidth` を加える。`options` の `noteShare` と、メッセージの `noteShare` はなくす。

表9：切替画面に関わるメッセージ

|---|---|---|---|

| Swift→JS | `switcher` | 切替画面 | `{notes, current, key, find, force, toggle, dismiss, picked}`：切替画面を開閉する。`current` は開いているノートの名前。`key` は、切替画面のウインドウにフォーカスがあるか。`find` が真なら検索欄に、偽なら一覧にフォーカスを置く。`toggle` が真なら、フォーカスの位置にかかわらず閉じる。`force` が真なら閉じない。`dismiss` が真なら、Esc でパネルも隠す。`picked` は、すぐに検索する文字列（§4.1） |

| Swift→JS | `open` | ノート | `{id, text, opening, land}`：ノートを開く。`land` は、`select` で受け取ったものをそのまま入れる。切替画面から開くとき以外はない。`keep` はなくす |

| Swift→JS | `notes` | 切替画面 | 一覧を更新する |
| Swift→JS | `focus` | 両方 | フォーカスを置く。切替画面のページは、一覧か検索欄のうち、フォーカスがあった場所に戻す |

機能ごとの置き場所を表 12 に示す。

`selectNextOccurrence`（⌘D）と `selectSelectionMatches`（⇧⌘L）は、CodeMirror の検索機能のキーの割り当てに入っていた。検索パネルをなくしても使えるように、この 2 つだけを割り当て直す。

### 6.3 意図した簡略化

次の 5 点は、コードを小さく保つために簡略にしている。コードには `// shortcut:` のコメントで記してある。

- 入力のたびに、全ノートの本文へ同一視の変換（§4.4）をかける。4 kB のノート 500 件で約 8 ms かかる。入力が遅れるようになったら、変換した本文を保持する。
- 一覧は、500 行に達したノートで打ち切る（§4.4）。
- 検索履歴は JS が持ち、アプリを終了すると消える（§4.7）。残すには、Swift に送って保存する。
- ディスプレイの左端との間は、切替画面を開くときだけ確かめる。開いている間に、手で、または ⌃⌘M で、パネルを左端へ動かすと、切替画面はディスプレイの外にはみ出す。
- 10 番目以降のピン留めにはキー表示がないので、ドラッグでは並べ替えられない。⌥↑ と ⌥↓ では並べ替えられる。

## 7. テスト

- `npm test`：文字の同一視、検索語の分割、ノート名の一致、並び順、すべての検索語を求める条件、1 行目の扱い、一致行の文面を試験する。
- `npm run smoke`：ヘッドレスの Chrome で、ノートのページと切替画面のページを、それぞれ別のウインドウで動かす。Swift の中継は試験が代わりに行い、各ページが送るメッセージと、受けたメッセージでの動作を確かめる。切替画面のページでは、エディタを隠してウインドウいっぱいに出ること、⌘P と ⌘F で開いたときのフォーカスと選択中の行、開閉の切り替え（`find`、`force`、`toggle`、`key`）、見出しと一致行の並び、起点のノートの順、`select` の `land` と `marks`、検索欄の ↩ と一覧の ↑↓、Tab、行と見出しのクリック、`picked` での検索、検索履歴、フォーカスの戻し先、`dismiss` と `escape`、`close`、`current`、キー表示のドラッグ、左端のドラッグでの `sideWidth`、ウインドウの高さの上限。ノートのページでは、`land` での選択と印、書き換わった本文での印、`marks`（以前の版の画面を閉じないこと、空の文字列で印が消えることを含む）、`findText()`。
- CI：`NotepanelChecks` とユニバーサルビルド、`npm test`、`npm run smoke`。`web/editor.js` が `editor/src` から作り直したものと一致するかも確かめる。

## 8. 採らなかった案

検討したうえで採らなかった案を、理由とともに表 13 に示す。

表13：採らなかった案と理由

| 分類 | 案 | 採らなかった理由 |
|---|---|---|
| 画面の構成 | パネル全体を覆い、一覧の下にプレビューを置く（現行） | 行を選んだまま、ノートの全体を見られない。検索欄の ↑↓ を行の選択に使うので、検索履歴に ↓ を使えない |
| 画面の構成 | 切替画面を、パネルの幅の中でノートの左に並べる | ノートの幅が減り、開くたびにノートの折り返しが変わる |
| 画面の構成 | 開いている間、パネルを切替画面の幅だけ左へ広げ、その左の部分に切替画面を置く（この設計の 1 つ前の試作） | タイトルバーもパネルと一緒に伸び、開くと一覧ボタンが左へ動く。同じ位置をもう一度押しても閉じられない |
| 画面の構成 | 切替画面のウインドウに影を付ける | キーウインドウになると、影が角の丸みに沿わず、四角い枠に沿って付く。角が尖って見える |
| 画面の構成 | 開いている間だけ、ノートの Web ビューを、切替画面とノートを覆う別のウインドウに移す | ページを 2 つに分けずに済むが、ゴミ箱へ移す前の確認（パネルのシート）がそのウインドウの下に隠れる。開閉のたびに Web ビューをウインドウの間で動かすので、ノートが一瞬消えるおそれもある |
| 画面の構成 | 一覧の左右と上下に余白を置く | 選択中の行の枠の外に、使わない余白が残る |
| 画面の構成 | 並べ替え専用のつまみを行の左に置く（現行） | ノート名に使える幅が減る。キー表示をつかめば足りる |
| フォーカス | 検索欄と一覧の間を ↑↓ で移る | 検索欄の ↑↓ を検索履歴に使えなくなる。⌘P で一覧に、⌘F で検索欄にフォーカスを置けば足りる |
| フォーカス | 検索欄にフォーカスを置いたまま、↩ と ⇧↩ で一致を順に送る | 一覧の ↑↓ と同じことをする、別の操作になる。↩ で一覧へ移せば、操作は 1 つで済む |
| 検索 | エディタの検索パネル（置換、⌘G）を残す | 検索が 2 つになる。短いメモを書くための道具に、置換までは要らない |
| 検索 | 選択した文字列で ⌘F を押したとき、選択した箇所の一致を選ぶ | 入力して ↩ を押したときと、動作が変わる |
| 検索 | いずれかの検索語を含むノートを結果にする | 検索語を足すと結果が増え、絞り込めない（§4.4） |
| 検索履歴 | ← → で検索履歴をたどる | 検索欄のカーソルの移動と重なる（§4.7） |
| 検索結果の表示 | 一致箇所を太字にする | 下線で足りる |
| 検索結果の表示 | ノート名を左の列、一致行の文面を右の列に並べる | 同じノートの 2 行目以降で、左の列が空白になる。列の幅を固定すると広すぎることが多く、狭くするとノート名が切れる |
| 検索結果の表示 | スクロール中も、ノートの見出しを一覧の上端に固定する | 見出しと下の行の文字が重なり、見た目が悪い。一致行の上に 1 行分の余裕を残す方法（§4.5）に替えた |
| ノートの表示 | 選択中の行のノートを、開かずに一時的に表示する | 開いているノートの状態を退避して戻す処理がエディタに入り、戻し損ねるとノートを編集できなくなる（§4.6） |

## 9. 既知の制約と未確認の項目

既知の制約は、次のとおりである。

- ノートの中の置換と、⌘G による次の一致への移動がない。
- Web ビューが 2 つになり、ページを 2 つ読み込んでおく分、メモリを使う。
- 切替画面のウインドウにフォーカスがある間は、パネルはキーウインドウでなくなる。

画面の動作は、ヘッドレスの Chrome でしか確かめていない。アプリが使う WKWebView とは、フォントと文字の描画が違う。Swift 側は CI でビルドしただけで、実機では動かしていない。実機では、次の点を確かめる。

- 切替画面を開閉しても、パネル、タイトルバー、ノートの位置と大きさが変わらない。一覧ボタンを同じ位置で 2 回押すと、開いて閉じる。
- 切替画面のウインドウが、パネルの左にすき間なく付き、上端がタイトルバーの下にそろう。高さは、ノート行がちょうど 10 行見えるところで止まり、パネルのほうが低ければ下端がパネルの下端にそろう。
- 切替画面にフォーカスがあってもなくても、角が 7 px で丸く、選択中の行の枠が下の角で欠けない。
- 切替画面のウインドウにフォーカスがある間の、パネルの信号機ボタンと影の見た目。
- 切替画面とノートの間で、クリックでフォーカスが移り、キー入力がフォーカスのある側に届く。最初のクリックが、行の選択やノートのカーソルの位置にも効く。
- 切替画面の左端をドラッグすると幅が変わり、次に開いたときも同じ幅になる。パネルを動かしたり大きさを変えたりすると、切替画面が付いてくる。
- ディスプレイの左端の近くで開くと、パネルが右へ動き、閉じると元の位置へ戻る。
- パネルを隠して（⌘W、ホットキー）また出すと、切替画面も一緒に消えて、また出る。
- 開いた直後に、前に開いたときの一覧や、空のウインドウが一瞬見えることがない。
- ⌘F が、ノート、検索欄、一覧、タイトルバーのノート名の入力中の、どこからでも働く。ノートで文字列を選択して ⌘F を押すと、その文字列で検索する。
- ゴミ箱へ移す前の確認を閉じた後、フォーカスが一覧に戻り、↑↓ でノートを移れる。開いているノートをゴミ箱へ移すと、代わりに開いたノートの行が選ばれる。
- 切替画面を開いたまま、⌘Y で以前の版の画面が開き、↑↓ と Esc が以前の版の画面に効く。切替画面は閉じない。
- 切替画面を開いたまま ⌃Tab でノートを移ると、一覧でもそのノートが選ばれる。
- 切替画面を開いたまま ⌃⌘M でパネルが動き、切替画面が付いてくる。
- 一致箇所の下線が、英字だけの行でも日本語の行でも欠けずに表示される。
- 日本語入力の変換中に、Enter、Esc、矢印キーが切替画面の操作にならない。
- 検索のホットキーで隠れていたパネルを出し、Esc を押すと、切替画面とパネルの両方が閉じる。
